# 澄境筆記 0.10.17

改善 macOS 主視窗的定位與頂部可用性。

- 初次建立視窗時，使用系統提供的可用範圍，排除選單列與 Dock；不再依賴首次顯示時由系統修正位置。
- 正常返回應用時不重設 macOS 的啟用模式與 Dock 顯示狀態；只有從背景代理模式回到主視窗才恢復。
- 顯示、取得焦點、還原、喚醒、解鎖及顯示設定變更後會檢查當下外框。只有頂部位於不可用區域或螢幕已移除時才做必要的校正；正常大小與位置保持不變。
- 使用同一套視窗與螢幕座標，支援負座標及不同縮放比例；尊重原生全螢幕，不把切回應用當成填滿或置中操作。
- 登入時啟動設定所保留的位置，恢復前會重新檢查目前螢幕範圍與視窗模式。
- 「顯示 → 記錄視窗位置診斷」可開關診斷紀錄，並開啟紀錄資料夾。預設關閉；只記錄事件、幾何位置、螢幕範圍、模式與頂部元件尺寸，不記錄筆記內容。紀錄有容量上限。

## 調查與驗證範圍

Electron 44.0.0 的原始版本，在測試機建立隱藏主視窗後得到 y=6，但可用畫面從 y=31 開始；首次顯示才由 macOS 修正。填滿後的外框與內容區域正確。這是已確認的定位缺口，並不是「閒置後偶發遮蓋」的完整根因證明。

驗證涵蓋隔離 Electron 主程式中的初始定位、顯示／隱藏、最小化還原、原生填滿、正常返回不變、內容排版、短暫閒置及模擬工作範圍變更後的單次修復；單元測試涵蓋負座標、多螢幕、不同縮放、原生／簡易全螢幕保護、鎖定與喚醒事件，以及取消待執行檢查。實際睡眠、解鎖、外接螢幕接拔與長時間偶發情況尚待實機驗證。完整原生全螢幕測試需要未鎖定的互動式桌面，CI 的幾何測試不等於這項實測。

## English

This release improves macOS main-window placement and top-control accessibility.

- New windows use the system work area, excluding the menu bar and Dock, instead of relying on macOS to repair initial placement.
- Returning to an already visible app no longer reapplies its activation policy or Dock visibility. Background-agent returns still restore them when necessary.
- Lifecycle and display events trigger a check of current bounds. Only an inaccessible top edge or a disconnected display requires correction; ordinary placement and size remain unchanged.
- Window and display coordinates stay in DIP units, including negative origins and mixed display scales. Native full screen is protected, and activation never forces fill or centring.
- Login-item changes validate captured bounds and the current window mode before restoring geometry.
- Optional **View → Record window placement diagnostics** records geometry, display work areas, modes and top-control dimensions, never note text. It is disabled by default, can be turned off and has bounded log storage.

The baseline reproduced an initial hidden-window top at y=6 while the work area began at y=31; macOS repaired it on first show. This confirms a placement gap, not the complete cause of the intermittent idle-return symptom. Tests cover isolated native window operations, layout and simulated display/lifecycle changes. Physical sleep/unlock, monitor hotplug and long-duration intermittent behavior still require device verification; full native full-screen validation requires an unlocked interactive desktop.
