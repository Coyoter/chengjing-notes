# 澄境筆記 0.10.15

這次集中修復已確認的資料與操作問題，沿用原有介面風格。

## 資料與同步

- 寫完立即完整退出時，會先保存最後編輯並完成已啟用的 Google 增量同步；不需要同時開啟本機備份。失敗可重試、返回或仍然退出，待傳內容保留。
- 共享神經元以上傳內容的版本確認完成，上傳期間新增的編輯會繼續補傳。
- 長文分享先讀取完整來源，再顯示原本的分享預覽；不再把畫面摘錄當成全文。收取共享內容使用伺服器實際複製的快照。
- 刪除筆記中的母核取方塊時，保留另外新增的子待辦，接回仍存在的上層或成為獨立待辦。
- 一般項目符號不再被誤認為待辦；Checklist 計數不受 HTML 屬性順序影響。

## 效能與操作

- 看板只讀目前引用的卡片，開啟「加入現有卡片」才按需搜尋；長期累積的已完成待辦也改為按需讀取。
- 看板建立、放置、移動及排序改為原子交易，避免並發操作造成重複或互相覆蓋；新增後的詳情面板不再被舊查詢結果關掉。
- 第二大腦不再讓已完全淡出的待辦佔用分頁，也不讓本批次之外的連線擠掉本批次內連線。
- AI 回覆截斷時，可保存完整部分，但未完成的批次仍可重試。白板文字及區塊標題修改會正確更新白板版本。

## 介面

- 第二大腦工具列、標題與分頁控制依實際空間排列，放大字級或縮小視窗不再互相遮擋。
- 開著 AI 側欄時，反思區操作可換行，所有按鈕保持可見。
- 3D 畫布、霧色與面板使用同一個已套用的主題，包含跟隨系統切換。

## English

This release fixes confirmed data, interaction and performance issues while preserving the established visual style.

- Quitting immediately after editing now saves the final changes and completes enabled Google incremental sync, independently of local backup settings. Failed uploads remain queued; retry, return and quit-anyway choices are available.
- Shared-content acknowledgements use the version actually uploaded, so edits made during upload are sent afterward. Sharing previews read full source content; forks use the snapshot actually returned by the server.
- Removing a parent checklist item preserves independently created child tasks by reconnecting them to a surviving ancestor or making them standalone. Ordinary list items are not treated as tasks, and checklist counts no longer depend on HTML attribute order.
- Kanban reads only referenced cards; existing-card search and completed-task history load on demand. Atomic kanban operations prevent duplicate placements and conflicting reorders. Newly added cards retain their detail panel.
- Fully faded tasks and out-of-batch links no longer consume the current Second Brain budget. Truncated AI responses do not mark an incomplete batch as finished. Whiteboard text changes update the board version.
- Responsive Second Brain controls no longer cover the heading, reflection actions wrap in narrow workspaces, and the 3D canvas follows the applied light, dark, ink or system theme.

驗證涵蓋隔離資料、單元測試、實際 Electron 退出流程及桌面／手機瀏覽器回歸；自動化封裝驗證不等同所有裝置的實機測試。

Validation uses isolated data, unit tests, the real Electron quit flow and desktop/mobile browser regressions. Automated packaging checks do not represent testing on every physical device.
